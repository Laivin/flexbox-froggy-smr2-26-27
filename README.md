# Flexbox entre toda a clase 🐸

Proxecto colaborativo de **Aplicacións web (2º SMR)** no IES Chan do Monte.

A partir de [Flexbox Froggy](https://flexboxfroggy.com/#es), cada estudante terá asignado un nivel e creará unha solución HTML + CSS **propia**, que represente os elementos e a distribución requirida empregando Flexbox.

## Estrutura

- `index.html`: portada común dos 24 niveis (xestionada pola docente).
- `exemplo/`: exemplo resolto que explica `justify-content: flex-end`.
- `niveis/nivel-XX/`: dous ficheiros por nivel (`index.html`, `style.css`).

## O teu traballo

1. Resolve o nivel que che asignou a profesora na web Flexbox Froggy.
2. Abre `niveis/nivel-XX/` e substitúe o contido de exemplo para representar ese reto usando HTML e CSS propios.
3. Emprega `display: flex` e as propiedades que correspondan ao nivel. **Non utilices posicionamento absoluto para colocar as ras**, aínda que podes posicionar elementos decorativos como nenúfares.
4. Inclúe no HTML o número do nivel, o obxectivo e unha explicación curta da solución. Engade comentarios útiles no CSS.
5. Comproba localmente que a distribución é correcta e que `style.css` carga sen erros.
6. Envía a túa contribución mediante unha **pull request**. Na descrición indica o nivel, que propiedades usaches e como verificaches o resultado.
7. Entrega en Moodle a ligazón á túa pull request. Se se pide, achega alí a captura de Flexbox Froggy resolto.

Non inclúas nomes completos, datos persoais nin imaxes extraídas do xogo no repositorio público.

## Publicar sen instalar Git (con Fork e Pull Request)

1. A docente crea un repositorio **público** e carga estes ficheiros (extraendo antes este ZIP).
2. Cada alumno crea unha conta de GitHub, entra no repositorio e escolle **Fork** → **Create fork**.
3. Na súa copia, entra na carpeta do nivel e edita `index.html` e `style.css` (icona do lapis ou **Add file** → **Upload files**). Guarda mediante **Commit changes**.
4. Desde a copia, abre **Contribute** → **Open pull request** para propoñer cambios ao repositorio da docente.
5. A docente revisa a pull request, pode pedir cambios e finalmente pulsa **Merge pull request**.

Os pasos da interface poden variar lixeiramente segundo a versión de GitHub.

## GitHub Pages

No repositorio principal, ir a **Settings → Pages → Build and deployment → Deploy from a branch**. Escoller `main` e `/(root)` e gardar. A URL resultante adoita seguir a forma:

`https://USUARIO.github.io/flexbox-froggy-smr2/`

As páxinas publicadas son **públicas**; non compartas datos persoais no código.

## Criterios de revisión propostos

- Solución do reto e uso de Flexbox: 50 %.
- HTML/CSS claros, funcionais e comentados: 25 %.
- Explicación da solución: 15 %.
- Contribución en GitHub e pull request: 10 %.

A docente poderá adaptar estes pesos aos criterios de avaliación da programación.
